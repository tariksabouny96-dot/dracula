# HOOD NOVA 2.1 — Operational Planning Core

## Status
Controlled local development release. Not an autonomous or production-ready execution platform.

## Built in this release
- Persistent, owner-scoped mission records using a SQLite store under `~/.hood/nova21/`.
- Mission lifecycle: `AWAITING_APPROVAL` -> `PLAN_CREATED`, or `CANCELLED`.
- Explicit, single-use confirmation required before writing a deterministic Markdown planning artifact.
- Restricted `GET /api/operations`, `POST /api/operations/create`, `POST /api/operations/approve`, `POST /api/operations/cancel`, and authenticated `GET /api/operations/artifact/<id>`.
- Artifact SHA-256 receipts and integrity-checked download. No arbitrary output path parameters.
- Missions section UI with create, refresh, explicit approval, cancel, states and artifact download. Untrusted mission text uses textContent.
- Screen/mobile CSS and visible keyboard focus for new controls.

## Technical boundaries
- This release writes **local planning artifacts only**. It does **not** run agents, external commands, browser tasks, deployments, research or client jobs. Plans are deterministic templates, not generated by an LLM.
- Owner-only operations deliberately remain restricted until tenant-scoped orchestration and independent execution authorization are proven.
- Existing interactive chat is unchanged and cannot yet invoke these mission endpoints itself. Use the Missions section to create records.
- A receipt verifies bytes of the planning document, not that the business objective has been completed.
- Disk-level failure between writing an artifact and committing SQLite could leave an artifact without a completed mission state; recovery reconciliation remains to be implemented.
- `JarvisServer` uses process-wide handler class attributes; do not host multiple isolated instances simultaneously.
- Database encryption, multi-process write coordination and crash recovery are not guaranteed.

## Safe local validation
1. Back up the existing Hood directory, database and any secrets separately.
2. Extract the source into a clean development folder; do not overwrite the active installation without reviewing the diff.
3. Install project requirements inside an isolated virtual environment.
4. Run `python -m pytest -q tests/hardening/test_nova21_missions.py`.
5. Start Hood using its documented `hood_cli.py` entrypoint and authenticate as the owner.
6. Open **Missions**, create a dummy mission, review it, approve local plan creation, download and inspect the receipt and file.
7. Restart Hood and confirm the record remains; verify viewer accounts cannot access it.
